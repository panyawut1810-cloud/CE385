1. Error-first Callback
    แก่นของมัน: เป็นท่ามาตรฐานยุคแรกของ Node.js เวลาเขียนฟังก์ชันที่ต้องรอเวลา (เช่น ดึง DB หรือสั่ง setTimeout) เราจะไม่ return ค่าออกมาตรงๆ แต่จะส่ง callback(err, data) กลับไปแทน
    กติกาสำคัญ:
        -Parameter ตัวแรก ต้องเป็น Error ห้ามสลับ (ถ้าไม่มี error ให้ส่ง null)
        -พอสั่ง callback(err) ปุ๊บ ต้องแปะ return ไว้หน้ามันเสมอ เพื่อสั่งตัดจบฟังก์ชันทันที ไม่งั้นมันจะวิ่งไปทำงานบรรทัดล่างต่อจนพัง
    ข้อเสีย: ถ้าต้องดึงข้อมูลซ้อนกันหลายๆ รอบ โค้ดจะไหลไปทางขวาเรื่อยๆ จนกลายเป็น Callback Hell อ่านยากมาก

2. Promise & Chaining
    แก่นของมัน: ทางแก้ Callback Hell โดยเปลี่ยนจากการส่งฟังก์ชันเข้าไป เป็นการ ส่งกล่อง (Promise) ออกมาแทน
    สถานะของกล่อง:
        -สำเร็จสั่ง resolve(ค่า) => คนเรียกรับไปทำต่อผ่าน .then()
        -พัง/หาไม่เจอสั่ง reject(error) => โดดไปลง .catch() ทันที
        -ส่วน .finally() => ทำงานเสมอ ไม่ว่าจะรอดหรือร่วง เอาไว้ล้างไพ่/ปิด Connection
    ข้อดีของ Chaining: เราส่งต่อข้อมูลไปเรื่อยๆ ได้เหมือนสายพานการผลิต เช่น fetch => คำนวณเกรด => จัดฟอร์แมตข้อความ => console.log โค้ดจะอ่านจากบนลงล่าง เรียงสวยงามขึ้นเยอะ

3. Async/Await & ลำดับ vs ขนาน 
    แก่นของมัน: มันคือ Syntax Sugaring (หน้าตาหล่อๆ) ที่ครอบ Promise ไว้อีกที ทำให้เราเขียนโค้ด Asynchronous แต่หน้าตาเหมือนโค้ด Synchronous ปกติ
    การทำงาน 2 แบบ:
        -แบบตามลำดับ (Sequential): ใช้ for...of แล้วแปะ await ข้างในทีละตัว => ข้อดีคือเป็นสเต็ปชัวร์ๆ แต่ข้อเสียคือช้าสะสม (300ms + 300ms + 300ms = 900ms)
        -แบบขนาน (Parallel): ยิง request ออกไปพร้อมกันทั้งหมดด้วย .map() แล้วค่อยใช้ await Promise.all(...) มารอเก็บผลลัพธ์ทีเดียว => เวลารวมจะเท่ากับตัวที่ช้าที่สุดเท่านั้น (~300ms) ประหยัดเวลาไปได้ 3 เท่าเลย
    เรื่อง try-catch: try-catch จะจับ await ได้เพราะ await เปลี่ยน Promise ที่ถูก reject ให้กลายเป็น Error ที่พุ่งออกมาในสโคปนั้นพอดี ต่างจาก Callback ธรรมดาที่ Error มักจะไปหลุดอยู่อีกมิติหนึ่งของ Event Loop

4. Combinators ทั้ง 4 ตัว 
    อาจารย์ต้องการวัดว่าเราเลือก นักสืบ/ตัวจัดการกลุ่ม Promise ถูกงานมั้ย
        1.Promise.all (ห้ามพังแม้แต่อันเดียว): เหมาะกับเคสที่ต้องใช้ข้อมูลครบทุกส่วนเพื่อประกอบหน้าเว็บ (เช่น โฟรไฟล์ + ตารางเรียน + ประกาศ) ถ้ามีแค่อันเดียวพัง หน้าเว็บก็เปิดไม่ได้แล้ว ยอมโดน reject ทันที
        2.Promise.allSettled (ขอรู้ผลครบทุกตัว): เหมาะกับงานส่งแจ้งเตือนหลายช่องทาง (เช่น อีเมล, SMS, แอป) ถึง SMS จะพัง เราก็ยังอยากรู้ผลสรุปของอันอื่นอยู่ดี ตัวนี้จะรอจนจบหมด แล้วรายงานสภาพของทุกตัว
        3.Promise.any (เอาสำเร็จอันแรกสุด): เหมาะกับระบบ Mirror Server หรือข้อมูลสำรอง ขอแค่มีกี่เครื่องไม่รู้ เครื่องไหนตอบกลับมาสำเร็จเป็นตัวแรก เอาอันนั้นเลย! ตัวที่ล้มเหลวไปก่อนหน้าให้ข้ามไป
        4.Promise.race (แข่งความเร็วเพียวๆ): ใครเข้าเส้นชัยก่อนเอาอันนั้น (ไม่ว่าจะสำเร็จหรือล้มเหลว) ในโจทย์นี้เอามาทำ Timeout Control โดยเอา Promise ดึง DB มาวิ่งแข่งกับ Promise ตั้งเวลา 800ms ถ้า DB ดึงช้าเกิน 800ms ฝั่ง Timeout จะเข้าเส้นชัยก่อน แล้วดีดไปใช้ข้อมูลแคชทันที
